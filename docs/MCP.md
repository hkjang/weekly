# Weekly Analytics MCP

Weekly는 별도 프로세스 없이 `/mcp`에서 인증된 읽기 전용 MCP 도구를 제공한다.

## 연결

1. Weekly의 개인 설정에서 API/MCP 키를 발급한다.
2. MCP 클라이언트의 Streamable HTTP URL을 `https://<host>/mcp`로 설정한다.
3. `Authorization: Bearer wky_...` 헤더를 설정한다.

세션 쿠키도 웹 화면에서는 동작하지만 자동화/MCP 클라이언트에는 개인 키를 사용한다. 키에는 `mcp:read` 범위가 필요하다.

## 프로토콜

- JSON-RPC 2.0
- Streamable HTTP POST
- 기본 협상 프로토콜 버전: `2025-11-25` (`2025-03-26`, `2025-06-18` 호환)
- 구현 메서드: `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`
- **배치 요청**을 받습니다(한 번에 최대 20건). 2025-03-26 규격의 일부이며, 알림만 담긴 배치는
  본문 없이 `202 Accepted` 로 답합니다.
- 프로토콜 오류는 **프로토콜 안에서** 답합니다. 본문이 깨졌으면 HTTP 200 에
  `{"jsonrpc":"2.0","id":null,"error":{"code":-32700,…}}` 이 실립니다. 이전에는 제품의 REST
  봉투(`{"success":false,…}`)와 HTTP 400 으로 답해서, MCP 클라이언트에게는 서버가 죽은 것과
  구분되지 않았습니다.
- 서버가 이름을 모르는 최상위 필드(`_meta` 등)는 무시합니다.

## 인자와 거부

도구 인자는 **데이터베이스에 닿기 전에** 검사합니다. 날짜가 `YYYY-MM-DD` 가 아니면, 상태·범위·
상태필터가 선언된 값이 아니면, 무엇이 틀렸고 무엇이 허용되는지 문장으로 돌려줍니다
(`isError: true`). 호출자가 만든 실수는 서버 로그에 장애로 남기지 않습니다.

선언만 해 두고 검사하지 않으면 **조용한 0건**이 됩니다. `status: "제출됨"` 은 예전에
`{"total":0}` 으로 답했고, 그것은 "그런 보고는 없습니다"라는 사실로 보고됩니다. 한 턴을
더 쓰더라도 거부하는 쪽이 맞습니다.

## 도구

### weekly_submission_overview

입력:

```json
{"weekStart":"2026-01-05"}
```

사용자 권한 범위의 활성 사용자 수, 제출 수/제출률, 상태별 수, 이슈 수, 평균 진척도를 반환한다.

### weekly_reports_search

입력:

```json
{"weekStart":"2026-01-05","status":"APPROVED"}
```

일반 사용자는 본인, 팀장/조직장은 동일·하위 조직, 관리자는 전체 보고서를 최대 100건 조회한다.
반환 항목에는 본문이 아니라 요약 한 줄이 담긴다. 본문은 `weekly_report_detail` 로 이어서 읽는다.

`weekStart`는 그 날짜부터 7일을 덮는 보고서를 찾는다. 주차 시작 요일을 바꾸면
격자만 옮겨지고 이미 쓰인 보고서는 그 자리에 남으므로, 날짜가 정확히 같은 것만
찾으면 전환되는 주의 보고서를 하나도 반환하지 못한다. `weekly_submission_overview`
가 같은 주를 세는 방식과 같다.

### period_report_rollup

입력:

```json
{"kind":"QUARTER","period":"2026-Q3","scope":"TEAM"}
```

`kind`는 `WEEK`, `MONTH`, `QUARTER`, `HALF`, `YEAR`이며 생략하면 `MONTH`다. `period`는 각각 `2026-09-07`, `2026-08`, `2026-Q3`, `2026-H2`, `2026` 형식이고 생략하면 현재 기간이다. `scope`는 `SELF`(기본) 또는 `TEAM`이며 `TEAM`은 팀장 이상만 호출할 수 있다.

기간에 겹치는 주간보고를 취합해 다음을 반환한다.

- `items`: 동일 업무를 병합하고 반복 기재된 줄을 제거한 업무 목록. 업무별 수행 주차, 진척도 변화, 이슈 발생 주차, 병합된 원본 업무명을 포함한다.
- `insights`: 완료율, 평균 진척도와 기간 중 상승폭, 정체·이월·이슈 지속 건수, 보고 커버리지, 중복 제거 건수.
- `highlights`: `RISK`, `WATCH`, `GOOD`, `INFO` 등급의 판단 근거 요약.
- `trend`: 주차별 수행·완료·미착수·이슈 건수와 평균 진척도.

**응답 크기.** 화면은 표를 스크롤하는 사람에게 전부 보내지만, 이 도구를 부르는 쪽은
받은 것이 곧 전부입니다. 그래서 업무는 최대 100건, 기여자는 최대 20명이고, 그 위에
**64 KiB 상한**이 함께 겁니다. 상한은 **전선에 나가는 전부**를 셉니다 — 프로토콜이
같은 답을 `structuredContent` 와 텍스트 사본으로 두 번 요구하므로, 한 벌만 재면 부르는
쪽은 예산의 두 배를 받습니다. 실제로 그랬습니다: 3년치 배포에서 연간 집계가 업무를 264건
에서 5건까지 깎아 텍스트를 64,977 바이트에 맞춘 뒤, 그 옆에 71,471 바이트를 더 실어
**144 KB** 를 보냈습니다. 행 수만으로는 크기가 잡히지 않기 때문입니다 — 같은 100건이 한 달이면 108 KB,
한 해면 169 KB 였습니다. 행은 자기가 등장한 모든 주차의 문장을 싣고, 그 수가 기간마다
다릅니다.

상한에 걸리면 **무거운 것부터** 덜어냅니다. 먼저 주차별 이력(`weeks`)을 상위 5건까지
줄이고, 그래도 넘치면 목록 뒤에서부터 업무를 덜어냅니다. 이력을 버리면 이미 "상위 N건에만
있다"고 설명된 것을 잃지만, 업무를 버리면 **있었다는 사실조차 알 수 없는 것**을 잃기
때문입니다. 어느 쪽이든 `note`가 몇 건 중 몇 건인지와 크기 때문에 더 줄였다는 사실을
문장으로 적습니다. `itemsTotal`, `timelineItems`, `contributorsTotal` 이 그 숫자를 함께 담습니다.

### weekly_report_detail

입력:

```json
{"reportId":128}
```

보고서 한 건의 업무 목록(제목·금주 실적·차주 계획·이슈·건의사항·진척도), 상태, 검토자와 검토
의견을 그대로 돌려준다. `weekly_reports_search` 가 돌려준 `id` 를 넣는다.

권한은 화면과 같다(`canViewReport`). **볼 수 없는 보고서와 없는 보고서는 같은 문장으로
거부한다** — 둘을 구분해 답하는 것은 그 보고서가 있다고 알려 주는 것이기 때문이다.

팀장이 팀원 보고서를 재료로 삼아 쓴 보고서는 재료의 본문을 함께 싣지 않고 이름과 `reportId`
만 싣는다. 한 사람의 주를 묻는 질문에 부서 전체의 주를 안겨 주지 않기 위해서다 — 필요하면
그 `reportId` 로 이 도구를 다시 부르면 된다.

### weekly_missing_submitters

입력:

```json
{"weekStart":"2026-03-02"}
```

그 주차에 보고서를 내지 않은 사람의 **이름**을 권한 범위 안에서 돌려준다. 임시저장(DRAFT)은
제출로 세지 않으며, 보고서는 날짜가 아니라 그 7일을 덮는지로 찾는다 — 주 시작 요일을 옮긴
주에 회사 전체가 미제출자로 나오지 않게 하기 위해서다. `activeUsers`, `submitted`,
`missingTotal`, `submissionRate` 를 함께 담고 이름은 최대 100명까지, 그 이상이면 `note` 에
몇 명 중 몇 명인지 적는다. 각 사람의 `lastWeek` 는 마지막으로 제출한 주차다.

**팀장 이상만 호출할 수 있고, 그 밖의 계정에게는 목록에 아예 보이지 않는다.** 몇 명인지는
`weekly_submission_overview` 가 누구에게나 알려 주지만, 이름을 건네는 것은 다른 일이다.

### schedule_board_tasks

입력:

```json
{"from":"2026-05-01","to":"2026-05-31","scope":"TEAM","state":"OVERDUE"}
```

업무 상황판의 일정을 돌려준다. `from`·`to` 를 생략하면 이번 달이고 한 번에 최대 366일이다.
`scope` 는 `SELF`(본인) 또는 `TEAM`(소속 조직, 기본), `state` 는 `ALL`·`OPEN`·`DONE`·
`OVERDUE`(마감일이 지난 미완료)·`URGENT`(미완료 긴급)다.

각 줄은 담당자, 기간, 완료 여부, 중요도(`URGENT`/`IMPORTANT`/`NEEDED`/`NORMAL`와 한글 라벨),
SR ID 와 링크를 담는다. `summary` 는 조건에 맞는 **전체**를 센 수치이고, `tasks` 는 최대 100건이며
잘렸으면 `note` 가 그 사실을 적는다.

주간보고가 지난 주에 **한 일**이라면 이 도구는 지금 진행 중이거나 앞으로 **마감할 일**이다.

### weekly_endpoint_analysis

입력은 빈 객체다. 관리자만 호출할 수 있으며 최근 24시간 API별 호출 수, 평균/최대 처리시간, 서버 오류와 전체 오류율을 반환한다.

## 키 회전

개인 설정의 `모든 키 회전`은 사용자 `key_version`을 증가시키고 활성 키를 모두 폐기한다. 실행 중인 모든 MCP 연결은 다음 요청부터 인증에 실패하므로 새 키를 발급해 클라이언트에 반영해야 한다.
