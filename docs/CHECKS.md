# 검사 도구

이 저장소에는 `go test` 가 잡지 못하는 것을 잡는 검사가 아홉 개 있습니다. 하나하나가 **한 번 겪은 실패**에서 나왔고, 그 실패가 각 스크립트 첫머리에 적혀 있습니다.

여기 모은 이유는 하나입니다. 열두 개의 목적과 **값**이 서로 다른데, 그것을 알려면 열두 개의 소스를 읽어야 했습니다.

## 언제 무엇을 돌리는가

| 검사 | 무엇을 잡나 | 값 | 언제 |
|---|---|---|---|
| `version-check.sh` | 버전을 적는 일곱 곳이 어긋난 것 | 즉시 | **릴리스마다** |
| `openapi-check.py` | 계약에 없는 경로, 경로 없는 계약 | 즉시 | 경로를 더하거나 지웠을 때 |
| `modal-close-check.py` | 대화상자의 `×` 가 Escape 와 다른 질문을 하는 것 | 즉시 | 대화상자를 손댔을 때 |
| `guard-check.py` | 자기 대상을 실행하지 않는 가드 시험 | **전체 7분** · `--changed` 로 1분 미만 | **`// guards:` 를 달거나 고쳤을 때** |
| `mutation-check.py` | 통과하지만 무엇도 지키지 않는 시험 | 가드당 수 분 | 새 시험을 썼을 때, 또는 한 계층을 훑을 때 |
| `authz-check.py` | 거절 규칙을 지우면 조용해지는 시험 | 수 분 | 권한 규칙을 손댔을 때 |
| `scale-check.py` | 규모에서만 보이는 응답 크기·지연·상한 표기 | 배포 하나 필요 | 조회 경로를 손댔을 때 |
| `load-check.py` | 월요일 아침의 동시성 — 특히 메모리 | 배포 하나 필요 · **데이터를 덮어씀** | 인증·저장 경로를 손댔을 때 |
| `backup-check.sh` | 복구 스크립트가 실제로 되돌리는지 — 첨부와 **비밀의 두 쪽** 모두 | 컨테이너 필요 | 백업·복구를 손댔을 때 |
| `release-check.sh` | 태그는 있는데 릴리스가 없는 것 | 즉시 | 릴리스 뒤 |
| `install-check.sh` | 받은 파일 그대로 설치가 **시작조차 되지 않는** 것 | 즉시 · docker 필요 | **릴리스마다** · 배포 파일이나 환경변수를 손댔을 때 |
| `number-check.py` | 화면의 숫자가 데이터베이스의 숫자와 다른 것 | 배포 하나 필요 | 집계·기간 계산을 손댔을 때 |
| `a11y-check.py` | 이름 없는 입력 칸, **키보드로 닿지 않는 클릭 자리**, 그리고 `--overlays` 로 **오버레이의 초점** | 배포 하나 · 브라우저 필요 | 화면에 입력 요소·클릭 행·오버레이를 더했을 때 |
| `paging-check.py` | **잘린 목록에서 나머지로 가는 길**이 없는 화면 | 없음 | 목록 화면을 더하거나 목록의 상한을 손댔을 때 |

CI 는 이 중 `go test`·`go vet`·`guard-check`·`modal-close-check`·`openapi-check`·`version-check`·`release-check`·`mutation-check --changed` 를 돌립니다. 릴리스 워크플로는 **산출물을 망가뜨릴 수 있는 것만** 돌립니다 — 잘못된 가드 표시는 tarball 을 망가뜨리지 않으므로 거기 없습니다.

## 화면을 걷기 위한 도구

검사는 아니지만 같은 이유로 있습니다 — **데이터가 없는 화면에서는 결함이 보이지 않습니다.**

| 도구 | 무엇을 세우나 |
|---|---|
| `seed-scale.sql` | 조직 46 · 사람 305 · 52주 · 보고 항목 110,534. 한 축이라도 납작해지면 **스스로 실패합니다** |
| `fake-ai-gateway.py` | AI Gateway 자리. 요청의 JSON Schema 를 읽어 그것을 만족하는 답을 돌려줍니다 |
| `fake-confluence.py` | Confluence Server 6.9.1 자리. 연동이 실제로 부르는 REST 두 개에 답합니다 |
| `seed-captures.py` | 화면 캡처 첨부. 제품의 업로드 경로로 올려 행과 파일이 함께 생깁니다 |

AI 를 쓰는 기능 셋 — **초안 작성 · 결정 제안 · PPTX 가져오기** — 은 씨앗으로 켤 수 없습니다. 그래서 씨를 뿌린 배포에서 그 화면들은 언제나 *"AI Gateway가 비활성화되어 있습니다"* 만 보여 주고, 뒤의 경로는 단위 시험 말고는 아무도 걷지 않습니다.

```
python3 scripts/fake-ai-gateway.py 18800
```

같은 서버가 `/v1/embeddings` 도 답하므로 **의미 검색**도 걸을 수 있습니다. 돌려주는 벡터는 글자에서 결정적으로 만든 것이라 같은 글은 언제나 같은 벡터가 되고 글자를 나눠 쓰는 두 글은 서로 가까워집니다. 검색 결과의 *의미*를 판단하는 데는 쓸 수 없지만, 임베딩 작업자·저장·차원·유사도 질의·화면이 실제로 도는지는 이것으로 확인할 수 있습니다. `관리자 설정 → 검색` 에서 임베딩 Endpoint 를 같은 주소의 `/v1/embeddings` 로, 모델은 아무 이름으로 넣습니다.

그리고 `관리자 설정 → AI Gateway` 에 `http://host.docker.internal:18800/v1/chat/completions` 와 아무 모델 이름을 넣습니다. 컨테이너는 `--add-host=host.docker.internal:host-gateway` 로 띄웁니다.

어떤 계약은 값을 지어내서는 만족시킬 수 없습니다. Confluence **분류기**는 넘겨받은 *모든* 문서에 대해 판단을 내놓아야 하고, **요약기**는 각 사실이 어느 문서에서 나왔는지 대야 합니다. 지어낸 식별자로 답하면 제품이 — 옳게 — 거절하고, 그러면 동기화의 AI 절반이 통째로 걷히지 않은 채 남습니다. 그래서 게이트웨이는 **요청에 실린 `pageId` 를 거둬** 그대로 돌려줍니다.

돌려주는 값은 자리마다 다릅니다. 111건이 같은 제목 하나를 나눠 가지면 화면이 묶는지 정렬하는지 중복을 걸러 내는지 알 수 없고, `kind` 가 늘 첫 번째 값이면 **금주 실적**만 채워져 그 옆의 두 열은 아무것도 증명하지 못합니다.

모델이 아닙니다. 돌아오는 글은 **일부러 가짜인 티가 납니다** — 이 배포의 초안을 누가 모델이 쓴 것으로 오해하면 안 되니까요. 확인하는 것은 제품의 파싱·검증·신뢰도 처리·미리보기가 **실제 HTTP 왕복 위에서** 도는지입니다.

### Confluence 자리

연동은 **2,516줄, 라우트 열 개**인데 사내 Confluence 없이는 어느 배포에서도 켤 수 없습니다. 동기화·후보·작성자 매핑 화면은 씨를 뿌린 배포에서도 늘 비어 있습니다.

```
python3 scripts/fake-confluence.py 18900 --pages 120
```

`관리자 설정 → Confluence` 에 `http://host.docker.internal:18900` 을 넣습니다. 이 서버는 자격을 보지 않고 **받은 것을 로그에 적어** 연동이 무엇을 보냈는지 보여 줍니다. 매핑되지 않은 작성자를 일부러 섞으므로 *"누구인지 모르겠다"* 를 세는 자리도 0 이 아닌 값으로 확인할 수 있습니다.

돌려주는 문서는 제목부터 `[가짜]` 입니다 — 이 배포에서 만들어진 후보를 누가 진짜 사내 문서에서 온 것으로 오해하면 안 됩니다.

### 캡처 첨부

`seed-scale.sql` 은 첨부를 만들 수 없습니다. 첨부는 절반이 PostgreSQL 의 행이고 절반이 상태 볼륨의 **파일**이라, 행만 넣으면 기동 로그에 `attachment files are missing` 이 뜨고 캡처 패널이 전부 `파일 없음` 이 됩니다. 그래서 씨를 뿌린 배포의 첨부는 **언제나 0건**입니다.

```
python3 scripts/seed-captures.py --base http://127.0.0.1:19271 --users u1,u3,u5,u7,u9
```

제품의 업로드 경로를 그대로 씁니다 — 로그인하고 멀티파트를 보냅니다. 그래서 크기 상한·개수 상한·형식 검사·저장 경로·**같은 그림을 하나로 합치는 처리**가 모두 실제로 돕니다. 파일을 볼륨에 직접 놓지 않는 이유가 그것입니다.

장마다 색을 달리하고 앞뒤 배치를 둘 다 만듭니다. 처음에는 세 장이 같은 그림이라 제품이 **파일 하나로 합쳤고** — 옳은 동작이지만 그러면 순서도 배치도 확인할 수 없습니다.

## 두 가지 조심할 것

**`load-check.py` 는 읽기만 하지 않습니다.** `u1..uN` 의 **이번 주 보고서를 덮어씁니다.** 그래서 `--yes` 를 요구하고, 거부할 때 무엇을 덮어쓸지 그 자리에서 말합니다. 규모 시드를 뿌린 배포에만 겨누십시오.

**`guard-check.py` 는 가드 하나당 `go test` 를 한 번씩 돌립니다.** 200개면 7분입니다. 그래서 `--test NAME` 과 `--changed [BASE]` 가 있습니다. 표시를 하나 고쳤을 때 7분을 쓰지 않아도 됩니다 — 그 7분 때문에 실제로는 안 돌리게 되고, 그것이 v0.190.0 을 빨간불로 만들었습니다.

## 각 검사가 나온 실패

| 검사 | 그때 무슨 일이 있었나 |
|---|---|
| `guard-check.py` | 이름한 함수를 한 번도 실행하지 않는 시험이 통과하고 있었습니다 |
| `mutation-check.py` | 시험이 제품 로직을 자기 안에 베껴 두고 그 사본을 검사했습니다 |
| `authz-check.py` | 소유권 검사를 통째로 지워도 그 이름을 단 시험이 초록불이었습니다 |
| `modal-close-check.py` | Escape 는 물었고, 사람들이 실제로 누르는 `×` 는 말없이 버렸습니다 |
| `openapi-check.py` | API 키 폐기·로그아웃·의견 달기가 동작하는데 계약에 없었습니다 |
| `version-check.sh` | 일곱 곳 중 하나를 빠뜨린 릴리스가 나갔습니다 |
| `release-check.sh` | v0.150.0 이 태그만 남고 릴리스가 만들어지지 않았습니다 |
| `scale-check.py` | 23.6MB 업무 목록, 새로고침마다 뒤바뀌는 순위, 아무도 그리지 않는 522KB |
| `load-check.py` | 월요일 아침 300명의 Argon2id 예약이 컨테이너를 죽였습니다 |
| `install-check.sh` | compose 가 요구하는 변수를 `.env.example` 이 비워서 보냈습니다. 고객이 문서대로 채우면 **첫 명령이 렌더조차 되지 않았습니다** |
| `a11y-check.py` | 입력 요소 62개 중 7개에 이름이 없었고, 그중 하나가 **주간 요약**이었습니다. 그다음엔 네 화면의 표 행이 **클릭으로만 열렸습니다**. 그다음엔 전체화면 발표에서 Tab 열두 번 중 여섯 번이 **보이지 않는 뒤쪽 화면으로** 나갔습니다 |
| `number-check.py` | 아직 제품의 오류를 잡은 적은 없습니다 — 40개 조합이 전부 맞았습니다. 대신 **검사 자신이 두 번 틀렸고**, 그 두 가지가 이 도구에 적혀 있습니다: 기간은 걸친 주를 세지 시작한 주를 세지 않으며, 조직 범위의 업무 수는 무엇의 DISTINCT도 아닙니다 |
| `paging-check.py` | 관리자 사용자 목록이 **305명 중 100명**을 보여 주면서 나머지 205명 — 팀장 8명, 조직장 3명, 관리자 1명 — 으로 가는 단추가 없었습니다. 같은 파일의 감사 로그에는 이전·다음이 있었습니다. **검사 자신도 두 번 틀렸고**: 주소를 조립해 넘기는 네 곳을 못 봤고, 그다음엔 `export default function` 으로 시작하는 화면을 통째로 잃은 채 통과했습니다 |
| `backup-check.sh` | 모든 릴리스 노트가 복구를 권했고, 아무도 그것을 돌려 본 적이 없었습니다. 그 뒤에도 검사는 첨부만 보고 **비밀은 보지 않았습니다** — 첨부가 다 돌아와도 비밀이 안 풀리면 서비스는 기동조차 하지 않습니다 |
