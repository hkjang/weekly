Weekly 엔터프라이즈 사용자 가이드 (User Guide & Employee Manual)

문서 버전: v0.285.0
대상: 임직원 작성자, 팀장(검토/승인자), 조직 관리자, AI MCP 클라이언트 사용자
문서 개요: 주간업무보고 작성·자동 복제, 선택 팀원 자료, 팀 작성 권고, Keycloak 로그인, 승인·반려, PPTX 내보내기와 API·Streamable MCP 활용 매뉴얼

1. 개요

Weekly 서비스는 개인 업무 작성부터 팀 승인, PPTX 자동 내보내기까지 단일 화면에서 직관적으로 사용할 수 있는 주간보고 시스템입니다.

1.1 Keycloak 기존 세션으로 로그인

  • 관리자가 Keycloak OIDC를 켠 환경에서는 Weekly 세션 없이 앱을 처음 열 때 Keycloak 로그인 상태를 한 번 확인합니다.
  • 이미 Keycloak에 로그인돼 있으면 로그인 화면을 거치지 않고 원래 열려던 Weekly 화면으로 돌아옵니다. Keycloak 세션이 없으면 반복 이동하지 않고 아이디·비밀번호 또는 Keycloak SSO로 로그인을 고르는 일반 로그인 화면이 표시됩니다.
  • 작성 도중 Weekly 세션이 만료된 경우에는 자동으로 탭을 이동하지 않습니다. 화면에 쓴 내용을 지키기 위해 기존처럼 다른 탭에서 로그인하라는 안내를 표시합니다.
  • Weekly의 로그아웃은 Weekly 세션만 끝냅니다. 같은 탭에서는 자동 재로그인을 건너뛰지만 Keycloak과 다른 사내 서비스의 SSO 세션은 유지됩니다. 다시 들어오려면 Keycloak SSO로 로그인을 직접 누르십시오.

2. 주간업무보고 작성 및 제출 (Employee Workflow)

2.1 작성 화면 구성

  • 주차 선택: 상단 주차 선택 드롭다운에서 작성 타겟 주차(예: 2026년 32주차) 선택.
  • ReportItem 항목 추가:
    • 금주 실적 (This Week): 금주 완료된 주요 실적 항목 작성
    • 차주 계획 (Next Week): 차주 진행 예정 업무 및 달성 목표 작성
    • 이슈 및 지원요청 (Issues): 리스크 항목 및 타 부서 지원 필요사항 작성
    • 진척도 (%): 업무 완료 비율 입력
  • 주차 시작 요일이 바뀐 주: 관리자가 주차 시작 요일을 바꾸면 그 다음 한 주 동안만 주차 표기가 이전과 달라집니다. 작성 화면은 이번 7일을 덮고 있는 기존 보고서를 그대로 열어 주므로 이어서 쓰면 됩니다(v0.282.0부터). 같은 기간에 보고서를 새로 만들 수는 없습니다.

2.2 승인 제출 신청 (Draft ➔ Submitted)

  • 내용 작성이 완료되면 하단의 [승인 요청 / 제출] 버튼 클릭.
  • 상태가 SUBMITTED로 전환되며 담당 팀장의 검토 대상이 됩니다.

2.3 내 보고서 수정·삭제

  • 현재 보고서와 과거 보고 상세 화면에서 본인 보고서를 수정하거나 삭제할 수 있습니다.
  • 주간 요약·금주 실적·차주 계획·이슈·상위 조직 요청 입력창은 내용의 줄 수와 화면 폭에 맞춰 자동으로 늘어납니다. 내용을 지우거나 화면이 넓어지면 다시 줄어들며, 입력창 안을 따로 스크롤하지 않고 페이지를 스크롤해 전체 내용을 확인할 수 있습니다.
  • 동시 변경을 덮어쓰지 않도록 버전을 확인합니다. 충돌하면 새로고침하지 말고 저장을 한 번 더 누르십시오 — 화면에 쓴 내용은 그대로 남아 있고, 새로고침은 그것을 지웁니다. 안내 문구도 그렇게 말합니다.
  • 제출·승인·확정된 보고서를 수정하면 기존 검토 결과가 해제되고 DRAFT로 돌아갑니다. 수정 후 다시 제출해야 합니다.
  • 검토 절차를 쓰지 않는 배포(workflow.enabled = false)에서는 제출이 곧 확정(CLOSED)이며, 확정본을 고쳐도 같은 규칙이 적용됩니다. 내용이 바뀐 보고서는 더 이상 확정된 그 보고서가 아니기 때문입니다.
  • 삭제는 확인 창을 거치며 보고 항목·댓글·상태 이력도 함께 제거되므로 복구할 수 없습니다.

2.4 과거 보고서 복제

  • 과거 보고 상세에서 복제를 누르고 대상 주차를 선택합니다.
  • 업무 구조만 복제는 분류와 제목만 옮기고 주간 요약, 실적, 계획, 이슈와 진척도를 초기화하므로 새 주차 작성에 권장합니다.
  • 전체 내용 복제는 원문 전체를 옮기며 반복 업무를 편집해 사용할 때 적합합니다.
  • 복제본은 항상 DRAFT로 생성되고 승인 이력, 댓글, Confluence/PPTX 연결과 원본 항목 ID는 복사하지 않습니다.
  • 같은 대상 주차에 보고서가 이미 있으면 덮어쓰지 않고 충돌을 안내합니다.

2.5 개인 설정의 주간보고 자동화

우측 상단 프로필 메뉴의 개인 설정 → 주간보고 자동화에서 선택한 뒤 자동화 설정 저장을 누릅니다. 두 기능은 기본으로 꺼져 있습니다.

지난주 보고서 전체 자동 복제

  • 모든 사용자가 켤 수 있습니다. 새 보고 주차가 시작되면 정확히 한 주 전 보고서의 요약과 업무별 구분·실적·계획·이슈·상위 조직 요청·진척도를 이번 주 DRAFT로 한 번 복제합니다.
  • 지난주 보고서에 업무 항목이 없거나 이번 주 보고서가 이미 있으면 건너뛰며, 기존 내용을 덮어쓰지 않습니다. 자동 초안을 삭제해도 같은 주에 매분 다시 만들지 않습니다.
  • 댓글·승인 이력·첨부 파일·Confluence/PPTX 출처는 옮기지 않습니다. 전체 내용이므로 끝난 실적과 지난 이슈도 들어옵니다. 이번 주 사실에 맞게 고친 뒤 제출하십시오.

팀원 작성 권고 메일

  • 팀장·조직장·관리자에게만 선택 항목이 보입니다. 월요일부터 일요일 중 고른 요일의 서비스 시간대 오전 9시 이후, 담당 범위에서 아직 제출하지 않은 활성 사용자에게 한 주에 한 번 보냅니다.
  • 바로 권고하려면 별도 팀원 작성 권고 메일 카드의 지금 권고 메일 보내기를 누르고 확인합니다. 이 버튼은 자동 발송 스위치와 선택 요일에 관계없이 이번 주 대상을 다시 확인하며, 자동화 설정을 켜거나 저장하지 않습니다.
  • 팀장과 조직장은 자기 조직의 하위 조직까지, 관리자는 전체 사용자를 대상으로 하며 권고한 본인은 제외됩니다. 여러 관리자의 범위가 겹쳐도 받는 사람은 같은 주에 한 통만 받습니다.
  • 사용자가 개인 설정의 주간보고 메일 발송에 저장한 주소가 있으면 그 주소로, 없으면 계정 이메일로 갑니다. 제출할 때 보내기를 켜는 것과는 별개입니다.
  • 수동 요청 뒤에는 권고 대상, 새로 발송 대기열에 넣은 인원, 이미 발송했거나 대기 중인 인원과 주소가 없어 건너뛴 인원이 표시됩니다. 이 결과는 대기열 등록 결과이며 실제 SMTP 발송은 백그라운드에서 이어집니다.
  • 관리자가 SMTP를 아직 설정하지 않았다면 화면에 그 사실이 표시되고 수동 발송 버튼은 비활성화됩니다. 자동 발송은 현재 주 안에 메일 설정이 정상화되면 선택한 요일이 지난 경우에도 뒤늦게 시작합니다.
  • 메일을 보내기 전에 보고서가 제출되거나 권고자의 역할·조직 범위가 바뀌면 예약된 권고는 취소됩니다. 자동으로 만든 예약은 자동 발송 설정을 끈 경우에도 취소되지만, 직접 요청한 예약은 자동 설정과 독립적으로 유지됩니다.

2.6 선택 팀원 주간보고 자료

팀장·조직장·관리자는 개인 설정 → 팀원 주간보고 자료에서 본인 보고와 함께 표시할 팀원을 고를 수 있습니다. 처음에는 아무도 선택되지 않습니다.

  • 이름·아이디·조직으로 검색하고 체크박스로 팀원을 고릅니다. 화면의 선택 수/500명 선택 배지와 최대 500명까지 선택 안내로 상한을 확인할 수 있습니다. 전체 선택은 선택 가능 목록의 앞 500명까지만 고르며 전체 해제로 모두 풀 수 있습니다.
  • 포함 설정 저장을 누릅니다. 팀장과 조직장은 본인 조직과 전체 하위 조직의 활성 사용자, 관리자는 전체 활성 사용자를 선택할 수 있으며 본인은 목록에서 제외됩니다.
  • 보고서를 열면 선택한 팀원의 정확히 같은 주차 보고서가 팀원 주간보고 자료에 읽기 전용으로 표시됩니다. 초안·제출·승인·반려·확정 등 모든 상태가 대상이고 원래 상태가 함께 보입니다. 보고서가 없는 팀원도 이번 주 보고서가 아직 없습니다.로 표시됩니다.
  • 보고서 화면뿐 아니라 발표 모드, PPTX와 제출 메일에서도 본인 내용 뒤의 별도 선택 팀원 포함 자료 구획으로 표시됩니다.

이 설정은 팀원의 보고서를 내 보고서로 복사하지 않습니다. 내 업무 항목·상태·버전과 팀원 원본은 그대로이며, 선택한 팀원이 다시 포함한 사람의 자료까지 이어 붙이지도 않습니다. 기간 보고·팀 종합·업무 추적·관리자 분석에도 내 업무로 중복 집계되지 않습니다.

포함 자료는 보고서를 열거나 출력을 새로 만들 때 현재 선택과 현재 권한으로 계산합니다. 따라서 선택을 바꾸면 과거 보고 상세도 그 과거 보고서와 정확히 같은 주차 자료를 새 선택으로 보여 줍니다. 역할 강등, 조직 이동 또는 팀원 비활성화로 접근 범위가 바뀌면 해당 자료는 즉시 숨겨지며, 이미 발송하거나 다운로드한 파일 자체는 바뀌지 않습니다.

3. 팀장 승인 및 검토 매뉴얼 (Team Leader Workflow)

관리자 설정에서 workflow.enabled = true 상태일 때 검토 및 승인 절차가 활성화됩니다.

[DRAFT (초안)] ➔ (임직원 제출) ➔ [SUBMITTED (제출 완료)] │ ┌───────────────┴───────────────┐ ▼ ▼ [APPROVED (승인 완료)] [REVISION_REQUESTED (보완 요청)]
  • 승인 (Approve): 보고 내용 확인 후 [승인] 버튼을 클릭하면 상태가 APPROVED로 확정됩니다.
  • 반려/보완 요청 (Revision Request): 보완이 필요한 경우 사유를 작성하여 [수정 요청]을 클릭하면 작성자에게 알림이 전달되며 REVISION_REQUESTED 상태로 되돌아갑니다.

4. PPTX 원클릭 내보내기 (PPTX Export)

  • 보고서 상세 페이지 또는 팀 종합 보고서 화면 상단의 [PPTX 다운로드] 버튼 클릭.
  • 시스템이 관리자에 의해 등록된 원본 PPTX 템플릿의 슬라이드 마스터, 레이아웃, 도형, 폰트를 그대로 유지한 채 {{THIS_WEEK}}, {{NEXT_WEEK}}, {{ISSUES}} 토큰 위치에 실시간 치환 결과를 파일로 다운로드합니다.

기본 4장 표 형식은 작성 순서를 바꾸지 않고 실적·계획 중 더 긴 내용과 예상 줄바꿈 수를 기준으로 업무를 균형 배치합니다. 하나의 업무 구분이 여러 장에 걸리면 각 장에 구분 제목이 다시 표시되며, 모든 업무 항목은 정확히 한 번 출력됩니다.

선택 팀원 포함 설정이 있으면 PPTX를 만드는 순간 같은 주차 자료를 임시 업무 항목으로 조합해 본인 항목 뒤에 이어서 출력합니다. 각 업무 분류 앞에는 선택 팀원 · 이름 (아이디)가 붙어 작성자와 원래 분류를 함께 구분하며, 보고서가 없는 팀원도 미작성으로 명시합니다. 기본·관리자 템플릿의 {{THIS_WEEK}}·{{NEXT_WEEK}}·{{ISSUES}}에는 이 순서로 내용이 들어가고, 내용량에 따라 기존 배치 규칙으로 페이지가 나뉩니다. 임시 항목은 내 보고서에 저장되거나 집계되지 않습니다.

5. API / MCP Key 발급 및 AI 에이전트 연동

  • 우측 상단 프로필 메뉴 ➔ [개인 API/MCP 키 관리]로 이동.
  • [신규 MCP 키 발급]을 클릭하여 wky_... 형태의 키 생성.
  • Claude Desktop 또는 Cursor의 MCP 설정파일(claude_desktop_config.json)에 아래와 같이 등록:
{ "mcpServers": { "weekly": { "command": "curl", "args": [ "-X", "POST", "-H", "Authorization: Bearer wky_58a1f90b2c3d4e5f", "https://weekly.internal/mcp" ] } } }

6. 자유 텍스트로 AI 작성

관리자가 AI 기능을 켠 경우 보고서 작성 화면에 AI로 초안 만들기 영역이 표시됩니다.

  • 이번 주 한 일, 다음 주 할 일, 이슈를 텍스트 영역에 자유롭게 붙여 넣습니다.
  • AI 분석을 누르고 구조화된 항목과 신뢰도·경고를 확인합니다.
  • 제목, 분류, 금주 실적, 차주 계획, 이슈와 진척도를 직접 수정합니다.
  • 기존 편집 내용에 병합하거나 분석 결과로 교체합니다.
  • 일반 보고서 편집 화면에서 최종 확인한 뒤 저장합니다.

AI 분석 결과는 미리보기일 뿐 자동 저장되지 않습니다. 서로 독립적인 한 일·할 일·이슈는 AI 응답 단계부터 개별 사실로 구분되고, 편집기에는 쉼표 나열 대신 한 줄 한 항목의 글머리표로 표시됩니다. 같은 구조가 PPTX의 개별 문단으로 출력됩니다. 분석 내용에 없는 사실이 추가되었거나 신뢰도가 낮게 표시되면 반드시 고친 후 적용하십시오.

7. 과거 PPTX 가져오기

개인 메뉴의 PPTX 가져오기에서 과거 보고 파일을 여러 개 선택할 수 있습니다.

  • PPTX 파일을 업로드합니다.
  • 작업 상태가 분석 완료 또는 확인 필요가 될 때까지 기다립니다.
  • 자동 감지한 주차, 요약, 업무 구분과 항목별 원본 슬라이드·구분 신뢰도를 확인합니다.
  • 잘못 분류된 항목은 내용을 수정하고 위·아래 버튼으로 순서를 조정합니다.
  • 같은 주차 보고가 있으면 병합, 교체, 건너뛰기 중 하나를 선택합니다.
  • 저장할 파일을 선택해 확정합니다.

같은 파일을 다시 올리면 SHA-256 중복으로 표시됩니다. 분석 파이프라인이 개선되었거나 결과가 부정확하면 원본 보관기간 안에 최신 파이프라인으로 다시 분석을 눌러 해당 파일만 재처리할 수 있습니다. 이 동작은 화면에서 편집 중인 분석값을 버리지만 이미 확정한 보고서는 대상으로 삼지 않습니다.

날짜·항목·업무 구분 신뢰도가 낮거나 AI 입력 한도로 일부 슬라이드 내용이 잘린 확인 필요 파일은 기본 선택되지 않습니다. 잘림 경고에 표시된 슬라이드와 원본 내용을 검토한 뒤 직접 선택해야 하며, 관리자 주차 시작 요일과 다른 날짜는 확정할 수 없습니다. 같은 Import 작업에서 동일 주차 파일이 여러 개면 후속 파일은 기본적으로 병합 전략을 사용합니다. 사용자가 수정·확정하기 전에는 정식 주간보고 데이터가 생성되지 않습니다.

8. Confluence 자동 초안

관리자가 연동을 활성화하면 주간보고 화면을 열었을 때 이번 주 Confluence 작성·수정 활동에서 발견한 업무 후보가 이미 표시됩니다. 별도 Confluence 검색, 파일 가져오기 또는 Sync 버튼을 사용할 필요가 없습니다.

  • 정규화된 업무 제목, 금주 실적, 차주 계획, 이슈와 신뢰도를 확인합니다. 독립된 실적·계획·이슈는 한 행씩 표시됩니다.
  • Confluence 출처 N건을 펼쳐 원본 Page 제목·Space·Version을 확인합니다.
  • 필요한 내용을 직접 고친 뒤 초안 수정 저장을 누릅니다.
  • 업무가 아니면 제외, 보고에 사용할 항목이면 보고서에 반영을 누릅니다.
  • 일반 업무 항목에서 최종 검토한 뒤 임시저장 또는 제출합니다.

수정한 자동 초안은 다음 동기화가 덮어쓰지 않으며, 제외한 원본 Page는 같은 주차에 다시 나타나지 않습니다. 동기화 도중 원본 Page 버전이 바뀌면 혼합된 내용을 초안으로 만들지 않고 다음 동기화에서 다시 처리합니다. AI 요약의 각 사실은 근거가 된 입력 Page를 함께 가리키며, 서버가 알 수 없는 Page를 근거로 든 응답은 한 번 교정한 뒤에도 유효하지 않으면 결정적 원본 제목 후보로 대체합니다. 후보의 출처 링크에서 실제 문맥을 최종 확인하십시오. 보고서에 반영한 경우 출처가 Confluence 자동 초안으로 표시됩니다.
